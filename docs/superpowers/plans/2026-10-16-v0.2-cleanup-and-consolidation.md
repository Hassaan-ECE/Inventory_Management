# Inventory Management 0.2 — cleanup and consolidation

Date: 2026-10-16
Branch: `feature/0.2-cleanup` (from `main` at 0.1.4, `714a136`)
Status: **Phase 1 done (dev isolation + DEV tag); Phase 3 next**

## Goal

Ship 0.2.0 with the same features, less code, one storage layer, one sync engine, safe developer builds, and a test share that exercises every field combination. Nothing changes for users except the sync warning, the EVCS Storage/ME Storage menu, and a one-time local database merge.

## Hard constraints

- **0.1.4 clients must keep syncing during rollout.** 0.2 writes the same S: op, snapshot, and manifest formats into the same folders (TE schema v2, Storage schema v1, Lab catalog v2). Format changes wait for a later release, after everyone is on 0.2.
- **S: stays one stream per inventory.** A single database file on S: is not safe for several writers, and separate streams mean one inventory's problem can't stall the others.
- **No data loss on the local merge.** Old local files are kept as backups, counts and pending outbox ops are checked before switching, and failure leaves the old files in use.
- Every phase ends green: Rust tests, Clippy `-D warnings`, rustfmt, frontend lint, tests, and build.

Order: 1 → 3 → 4 (with the sync warning built once into the unified engine) → 2 → 5 → 6. The warning and the dev share both need the sync engine, so they come after it is unified instead of being written three times.

## Phase 1 — Developer safety (done 2026-10-16)

1. **Dev builds never touch live data.** Debug builds (`cfg!(debug_assertions)`) default to `.tmp/dev-data` for local databases and `.tmp/dev-share/modules/<folder>` for each shared root (`backend/src/platform/dev_build.rs`). The env overrides still win. Verified with `bun run dev:desktop`: databases created in `.tmp/dev-data`; no S: or `%LOCALAPPDATA%` writes.
2. **DEV badge.** One shared `StatusFooter` (`frontend/src/platform/ui/StatusFooter.tsx`) replaces the three copied footers; in dev builds its corner shows `DEV build` instead of the author credit.

## Sync warning (built in Phase 4)

When a module is skipping remote files, the footer shows a warning that stays visible until the problem clears. Files from a newer app version are reported as "update required", not as corrupt. Implemented once in the unified engine as a structured `warning` on the shared status (not text appended to the message, which the 0.1.4 update message overwrites).

## Phase 2 — Developer test share

- Fixture definitions in the repo, one per inventory, listing records that cover every field combination: empty/max-length, every status, archived, calibration states, quantities, unicode, duplicates, deletes, concurrent edits from two clients.
- A command builds the dev share through the real sync engine (ops, snapshot, manifest from several fake clients), so it looks exactly like the live share.
- Default location `.tmp/dev-share`; an option writes to an S: dev folder for two-PC testing.
- **Rule:** every new field or feature adds fixtures in the same change.

## Phase 3 — Remove dead code and placeholders

Each removal is recorded in `docs/engineering/REMOVED_AND_FUTURE.md` (what it was, why it went, the commit to restore from).

Removal list (from the 0.1.3 code review):
- ME Storage placeholder module and placeholder shell chrome.
- InventoryApps pilot root constants.
- Window-state save/restore (disabled on purpose).
- Unmounted/unused UI: `ImportDialog`, `ColumnMenu`, `ViewSettingsMenu`, `useMediaQuery`, `toggle.tsx`.
- Lab v1 UI (~3,250 lines), Lab v1 sync copy, Lab v1 model/mutations/query, legacy Lab v1 workbook export. **Gate:** confirm no PC still holds an unmigrated v1 Lab database. On 2026-10-16 the v1 ops folder on S: is empty and catalog-v2 has two clients.
- One-time live repair tests (`REPAIR_TE_LEGACY`, `REPAIR_LAB_OUTBOX`), Roaming DB copy, legacy SQLite quarantine.

## Phase 4 — One local database, one sync engine, backend restructure

- One `inventory-management.feox` per PC, keys namespaced per inventory; a one-time startup merge from the three current files.
- One storage wrapper and one inventory-entry sync engine, generic over the record type. TE and EVCS Storage plug in; Lab catalog sync moves onto the same file/lock/snapshot helpers.
- The backend layout matches the frontend:
  - `platform/` holds the database, sync engine, paths, and runtime;
  - `modules/<inventory>/` holds the model, commands, queries, mutations, and export;
  - TE moves out of the top level into `modules/te_test_equipment/`.
- The divergence and restore tests from 0.1.4 must pass unchanged in meaning.

## Phase 5 — Types and file size

- Generate TypeScript types and response guards from the Rust types (specta or ts-rs) in place of `bridgeGuards.ts` / `labBridgeGuards.ts`.
- Split files over ~500 lines along real seams: `catalog_sync.rs`, `api/commands.rs`, `PartDialog.tsx`, `TeLabComponentsView.tsx`, `CalibrationRosterDialog.tsx`.

## Phase 6 — Release 0.2.0

- Version bump, release notes, signed build, two-PC rehearsal on the dev share, live local-DB merge rehearsal on copies of real databases, S: staging, GitHub release.

## Clean code rules for this work

- One way to do each thing; no copies.
- Names say what the code does in user terms.
- Small modules with one job.
- Comments explain *why*, not *what*.
- No dead code, feature flags for removed features, or placeholders.
- Every behaviour change ships with a test that fails without it.
